# Rust-only work: another-PC handoff

## Read this first

This is the Rust repository: `simdorei/codex-discord-remote-rust`, branch `main`.
The older Python repository is a separate checkout and was not committed here.
The user requested a trial of the new bot binary, duplicate checks, and publication
so development can continue on another PC because app-server errors are frequent.

This publication is not a long-run stability certificate. Do not relabel previous
memory-test failures as passing, or rerun tests repeatedly to obtain a desired result.

## Local trial and remaining work

The requested immediate trial is a runtime-binary update through the existing
identity-bound live-handshake maintenance path. It requires a verified old process,
pre/post-stop database snapshots, a checked candidate, normal shutdown, one new
process, and increasing fresh heartbeats. No safety markers are forcibly removed.

The request controlling the update itself is handled by the running bot. Therefore
the independent updater must wait for its completion before requesting shutdown.
Its subsequent Discord result, not the presence of this commit, proves deployment.
Duplicate verification checks whether that reply is replayed after the restart;
it is not a substitute for a new real-user request on the new version.

Full Rust-only launcher/plugin promotion and formal recovery-package certification
remain separate from this limited binary trial. Do not claim they are complete.
No app-server-error fix is claimed by this handoff. Preserve the exact next error
and inspect the failing request/response and selected Codex executable/profile.

## Continuing on another PC

1. Clone/pull this Rust repository and verify the branch/commit against the reported push.
2. Read `README.md` and `docs/python-free-migration.md` for native build/install commands.
3. Configure this PC's own local environment, Codex executable and project paths.
   Do not copy another PC's absolute paths or maintenance-ticket example paths blindly.
4. Keep `.env`, credentials, local databases, browser profiles, logs and backups out of Git.
5. Do not run two bot instances on different PCs with the same Discord bot token.
   Coordinate stopping the first PC before starting a replacement; development alone
   does not require starting a second production bot.
6. Before broader promotion, review the startup/memory-check contract with Pro,
   preserve genuine test outcomes, verify the current recovery package, and perform
   a short real Discord request/final-delivery check on the chosen production PC.

The one-off instrumented diagnostic was private and is not part of the product source.
